Gestión de la Calidad del Software

Qué significa "calidad" y cómo se sostiene durante todo el desarrollo

Conceptos clave, métricas de referencia, los estándares ISO 9126 y 25000, y las técnicas y herramientas que un equipo usa para asegurar que el software cumpla lo que promete.

Fundamentos

Los pilares conceptuales antes de entrar en procesos o metodologías.

¿Qué entendemos por calidad de software?

Es el grado en que un sistema cumple los requisitos funcionales explícitos, además de expectativas implícitas de uso: que sea confiable, fácil de mantener y agradable de usar.

Funcionalidad hace lo que promete
Confiabilidad se comporta de forma estable
Usabilidad es fácil de aprender y usar
Mantenibilidad es fácil de modificar

ISO/IEC 9126

Norma que definió un modelo de calidad de producto de software organizado en seis características principales.

  • Funcionalidad — adecuación, exactitud, interoperabilidad y seguridad.
  • Fiabilidad — madurez, tolerancia a fallos y capacidad de recuperación.
  • Usabilidad — facilidad de comprensión, aprendizaje y operación.
  • Eficiencia — comportamiento en tiempo y uso de recursos.
  • Mantenibilidad — facilidad de análisis, cambio y prueba.
  • Portabilidad — adaptabilidad a distintos entornos.

Familia ISO/IEC 25000 (SQuaRE)

Sucesora de la ISO 9126: reorganiza el modelo de calidad en dos vistas complementarias y agrega procesos de evaluación.

  • Calidad en uso — eficacia, satisfacción, confianza y seguridad al usar el producto en contexto real.
  • Calidad de producto — ocho características, incluyendo compatibilidad y seguridad como nuevas dimensiones.
  • Incluye guías de medición (25020) y de requisitos de calidad (25030), además del modelo en sí.

Técnicas de aseguramiento de la calidad

Niveles y tipos de prueba que se aplican durante el desarrollo.

Pruebas unitarias

Comprueban el funcionamiento de componentes individuales del software.

Pruebas de integración

Verifican que los diferentes componentes funcionen correctamente al trabajar juntos.

Pruebas de sistema

Evalúan el sistema completo para comprobar que cumpla con los requisitos establecidos.

Tipos de pruebas

Herramientas de Calidad

Herramientas utilizadas para gestionar pruebas, errores y calidad del software.

Jira

Bug Tracker

Permite registrar, organizar y realizar seguimiento de errores y tareas durante el desarrollo.

Bugzilla

Bug Tracker

Herramienta utilizada para registrar y realizar seguimiento de errores encontrados en el software.

ESLint

Linter

Analiza código JavaScript para detectar errores y problemas relacionados con las buenas prácticas.

TestRail

Zephyr

Test Management

Procesos de Desarrollo de Software

Cómo se organiza el trabajo, de la idea al software en producción

El ciclo de vida del desarrollo (SDLC) y los modelos tradicionales que durante décadas definieron cómo un equipo transforma requisitos en software funcionando.

Ciclo de vida del desarrollo (SDLC)

Las seis etapas por las que atraviesa todo proyecto de software.
01

Requisitos

Se relevan las necesidades del cliente y del negocio.

02

Diseño

Se define la arquitectura y el comportamiento del sistema.

03

Desarrollo

Se escribe el código que implementa lo diseñado.

04

Pruebas

Se verifica que el software cumpla lo requerido.

05

Despliegue

El software pasa a producción y queda disponible.

06

Mantenimiento

Se corrigen errores y se agregan mejoras post-lanzamiento.

Modelos tradicionales

Tres formas clásicas de estructurar el SDLC, cada una con sus propios trade-offs.

Modelo en cascada

Cada etapa del SDLC se completa por entero antes de comenzar la siguiente, en una secuencia lineal sin retroceso.

Diagrama del modelo en cascada y sus etapas.

Requisitos
→
Diseño
→
Desarrollo
→
Pruebas
→
Despliegue

Ventajas

  • Estructura simple y fácil de planificar
  • Documentación clara en cada etapa
  • Funciona bien con requisitos estables

Desventajas

  • Poca flexibilidad ante cambios
  • El cliente ve resultados muy tarde
  • Los errores de diseño se detectan tarde
Cuándo usarlo: proyectos con requisitos bien definidos y estables desde el inicio, y bajo riesgo de cambio.

Modelo en V

Extiende la cascada asociando cada etapa de desarrollo con una etapa de prueba equivalente, verificando desde el principio.

Diagrama del modelo en V y la relación entre desarrollo y pruebas.

Requisitos ↔ Pruebas de aceptación
·
Diseño ↔ Pruebas de sistema
·
Código ↔ Pruebas unitarias

Ventajas

  • La verificación se planifica desde el inicio
  • Detecta errores de diseño más temprano
  • Buena trazabilidad entre requisito y prueba

Desventajas

  • Sigue siendo rígido ante cambios
  • Poco espacio para prototipado temprano
  • Requiere requisitos muy detallados
Cuándo usarlo: proyectos donde la confiabilidad es crítica (sistemas médicos, aeroespaciales) y el costo de un error es alto.

Modelo iterativo e incremental

El sistema se construye en ciclos sucesivos, cada uno agregando funcionalidad sobre una versión previa ya funcional.

Diagrama del desarrollo iterativo e incremental.

Iteración 1
→
Iteración 2
→
Iteración 3
→
Versión final

Ventajas

  • Entrega valor funcional desde etapas tempranas
  • Permite ajustar el rumbo entre iteraciones
  • Reduce el riesgo de grandes fallas al final

Desventajas

  • Requiere una arquitectura pensada para crecer
  • Puede ser difícil de planificar y presupuestar
  • Exige comunicación constante con el cliente
Cuándo usarlo: proyectos con requisitos que pueden evolucionar, o cuando se necesita mostrar avances tempranos. Es la base conceptual de las metodologías ágiles.
